# MOEX Portfolio Risk

Проект по анализу недельных котировок акций Московской биржи и построению портфеля минимального риска.

Цель проекта — загрузить исторические данные по нескольким акциям, очистить и объединить их, рассчитать недельные доходности, построить ковариационную матрицу и найти веса портфеля, минимизирующие историческую дисперсию доходности.

## 1. Данные

В проекте используются CSV-файлы с недельными данными по акциям Московской биржи.

Каждый файл соответствует одной акции. Тикер акции извлекается из имени файла. Например:

```text
SBER_weekly.csv
GAZP_weekly.csv
LKOH_weekly.csv
```

В исходных данных используются следующие поля:

| Поле | Описание |
|---|---|
| `datetime` | дата недельной свечи |
| `open` | цена открытия |
| `high` | максимальная цена за неделю |
| `low` | минимальная цена за неделю |
| `close` | цена закрытия |

Для расчётов используется столбец `close`, потому что доходности считаются между ценами закрытия соседних недель.

Исходные CSV-файлы должны лежать в папке:

```text
data/
```

## 2. Методика расчёта

Для каждой акции берётся последовательность недельных цен закрытия.

Недельная доходность рассчитывается по формуле:

```text
r_t = P_t / P_{t-1} - 1
```

где:

- `P_t` — цена закрытия текущей недели;
- `P_{t-1}` — цена закрытия предыдущей недели.

После этого по таблице недельных доходностей строится ковариационная матрица доходностей.

Портфельный риск считается по формуле:

```text
w^T Sigma w
```

где:

- `w` — вектор весов акций в портфеле;
- `Sigma` — ковариационная матрица недельных доходностей.

Оптимизатор решает задачу:

```text
min w^T Sigma w
```

при ограничениях:

```text
sum(w_i) = 1
0 <= w_i <= 1
```

То есть весь капитал распределяется между выбранными акциями, а короткие позиции запрещены.

## 4. Основные модули

### `data_source.py`

Содержит класс `MoexCSVDataSource`.

Он отвечает за поиск CSV-файлов в папке с данными, извлечение тикера из имени файла и ленивое построчное чтение исходных данных.

Основные методы:

- `iter_csv_files()` — лениво возвращает пути к CSV-файлам;
- `extract_ticker()` — извлекает тикер из имени файла;
- `iter_price_rows()` — лениво читает один CSV-файл построчно и возвращает только дату, тикер и цену закрытия;
- `iter_all_price_rows()` — лениво проходит по всем CSV-файлам и возвращает строки с нужными полями.

### `processor.py`

Содержит класс `MarketDataProcessor`.

Он отвечает за обработку рыночных данных с помощью `pandas`.

Основные методы:

- `load_price_tables()` — загружает отдельные таблицы цен закрытия;
- `build_close_price_table()` — объединяет цены закрытия разных акций по общим датам;
- `calculate_returns()` — рассчитывает недельные доходности;
- `calculate_covariance_matrix()` — строит ковариационную матрицу доходностей.

### `optimizer.py`

Содержит класс `MinimumVarianceOptimizer`.

Он отвечает за поиск портфеля минимальной дисперсии.

Внутри используется оптимизация функции:

```text
w^T Sigma w
```

с ограничениями на сумму весов и неотрицательность весов.

### `exporter.py`

Содержит класс `ReportExporter`.

Он сохраняет результаты работы проекта в папку `results/`.

### `decorators.py`

Содержит собственный декоратор `execution_time`.

Он измеряет время выполнения выбранных функций проекта.

### `exceptions.py`

Содержит пользовательские исключения проекта.

Например:

- `MarketDataError`;
- `MissingDateError`;
- `EmptyDataError`;
- `PortfolioOptimizationError`.

## 5. Обработка данных в pandas

В проекте выполняются следующие шаги обработки данных:

1. ленивое чтение исходных CSV-файлов построчно через `MoexCSVDataSource`;
2. выбор только нужных полей: даты, тикера и цены закрытия;
3. преобразование полученных строк в табличный формат для дальнейших расчётов;
4. преобразование даты в формат `datetime`;
5. преобразование цены закрытия в числовой формат;
6. проверка пропущенных дат;
7. построение общей таблицы цен закрытия по тикерам;
8. сортировка временного ряда по дате;
9. расчёт недельных доходностей через `pct_change`;
10. построение ковариационной матрицы доходностей.

## 6. Потоковая обработка без pandas

В проекте используется ленивое построчное чтение исходных CSV-файлов без `pandas.read_csv`.

Класс `MoexCSVDataSource` сначала лениво перебирает CSV-файлы в папке `data/`, а затем читает каждый файл построчно через стандартный модуль `csv`.

Метод `iter_price_rows()` возвращает из каждой строки только нужные поля:

- дату;
- тикер;
- цену закрытия.

Это позволяет не загружать исходный CSV-файл целиком на этапе первичного чтения и не хранить лишние столбцы `open`, `high`, `low`.

Пример:

```python
def iter_price_rows(self, file_path):
    ticker = self.extract_ticker(file_path)

    with open(file_path, encoding="utf-8", newline="") as file:
        reader = csv.DictReader(file)

        for row in reader:
            yield {
                "datetime": row["datetime"],
                "ticker": ticker,
                "close": row["close"],
            }
```

Метод `iter_all_price_rows()` объединяет ленивое чтение всех файлов:

```python
def iter_all_price_rows(self):
    for file_path in self.iter_csv_files():
        yield from self.iter_price_rows(file_path)
```

После этого данные передаются в `MarketDataProcessor`, где уже собираются в таблицу для расчёта доходностей, ковариационной матрицы и оптимального портфеля.

## 8. Пользовательские исключения

В проекте определены пользовательские исключения для обработки ошибок.

Примеры ситуаций:

- отсутствуют CSV-файлы с данными;
- в таблице есть пропуск даты;
- оптимизатор не смог найти допустимое решение;
- сумма весов портфеля не равна единице;
- получены отрицательные веса.

Такие ошибки обрабатываются отдельно от стандартных исключений Python и делают поведение программы более понятным.

## 9. Декоратор

В проекте используется собственный декоратор `execution_time`.

```python
@execution_time
def build_close_price_table(self):
    ...
```

После запуска программы в консоли появляется сообщение вида:

```text

```

## 12. Тестирование

Для проверки проекта используется `pytest`.

Запуск всех тестов:

```bash
pytest
```

Тесты находятся в файле `test_portfolio_optimization.py`.

В тестах проверяются основные части проекта:

| Что проверяется | Описание |
|---|---|
| `MoexCSVDataSource` | поиск CSV-файлов, извлечение тикера, ленивое чтение строк из одного файла и из всех файлов |
| `MarketDataProcessor` | объединение цен закрытия, обработка пустой папки, обработка пропущенных дат, расчёт доходностей и ковариационной матрицы |
| `MinimumVarianceOptimizer` | корректность весов портфеля, обработка пустой таблицы доходностей и пропусков |
| `portfolio_variance` | вычисление дисперсии портфеля по формуле `w^T Sigma w` |
| `portfolio_variance_gradient` | вычисление градиента функции дисперсии |
| `ReportExporter` | создание папки результатов и сохранение файлов `CSV`/`JSON` |

В тестах используются возможности `pytest`, необходимые по требованиям проекта:

- фикстуры `@pytest.fixture` для создания временных CSV-файлов и объектов проекта;
- параметризация `@pytest.mark.parametrize` для проверки нескольких входных данных одним тестом;
- `pytest.raises` для проверки пользовательских исключений;
- пользовательская метка `@pytest.mark.optimization` для тестов оптимизатора;
- временные директории `tmp_path`, чтобы тесты не изменяли реальные данные проекта.

Отдельно проверяется новая ленивaя обработка CSV-файлов:

- `iter_price_rows()` возвращает только поля `datetime`, `ticker`, `close`;
- `iter_all_price_rows()` проходит по всем CSV-файлам и объединяет построчное чтение через генератор;
- лишние столбцы исходных файлов, например `open`, `high`, `low`, не попадают в результат ленивого чтения.
